# S3 Report Schemas

Reference for every report TryBooking exports to the S3 bucket `produk-rdsextracts-438255373632`. Generated by sampling the live files (June 2026).

> This is the technical, column-level reference. For a plain-English guide to what each report is *for* and the questions it can answer, see **`docs/notion/what_data_we_have.md`**.

## File layout

- **Path format:** `YYYY/MM/YYYYMM-reportname-TBUK.csv`
- **Monthly files** (`YYYYMM-…`) cover the current month and are overwritten daily.
- **Dated files** (`YYYYMMDD-…`) are point-in-time snapshots — `BookingDataAll` (the full history, written periodically) and `AccountMovementDaily` (one per day).
- Most files are a plain CSV with a header row. **Four files have a one-line metadata preamble** before the real header (see the ⚠️ note on those).

## Which reports the pipeline actually uses

| Report | Used by | Notes |
|---|---|---|
| Accounts | `prepare_data.py`, tiers, most reports | Core account master data |
| BookingData | `prepare_data.py` (daily upsert) | Current-month transactions |
| BookingDataAll | `prepare_data.py` (history seed) | Full transaction history (~2.2 GB) |
| Users | `prepare_data.py`, domain/commission reports | |
| RiskReport | event completion reminders, funds reminders | Balances + exposure |
| AccountBalance | (legacy / ad-hoc) | Superseded by RiskReport for most uses |
| AccountMovementDaily | funds/event reminders | Daily ledger movements incl. `Pending` |
| The rest | not currently consumed | Available if needed |

## Core reports

### Accounts (37 cols) — `YYYYMM-Accounts-TBUK.csv`
Account master data: identity, status, fees, tier/rating, location.

`Id`, `AccountName`, `AccountStatus`, `DateTimeCreated`, `IsVerified`, `BankAccountIsDeleted`, `BankAccountName`, `BSB`, `AccNumber`, `BankAccountStatusId`, `LastLogIn`, `FirstEventCreation`, `LastEventCreation`, `Industry`, `SubIndustry`, `GatewayGroup`, `DGRStatus`, `IsGstEnabled`, `ProcessingFeeOnline`, `ProcessingFeeBoxOffice`, `TicketFeeOnline`, `TicketFeeBoxOffice`, `DonationFeeOnline`, `DonationFeeBoxOffice`, `TierSystem`, `PreviousTier`, `YearsLoyalty`, `TicketQuantity`, `AccountRating`, `PreviousRating`, `RatingChanged`, `State`, `Postcode`, `Country`, `SchoolRecNumber`, `PromoCode`, `LastAccountTransactionDate`

> Note: the account ID column here is `Id` (not `AccountId`). Bank details (`BSB`, `AccNumber`, `BankAccountName`) are encrypted/hashed in the export.

### BookingData (39 cols) — `YYYYMM-BookingData-TBUK.csv`
Current-month transactions, refreshed daily. The most-used report.

`BookingId`, `BookingTransactionId`, `AccountId`, `AccountName`, `DateTimeCreated`, `EventId`, `EventName`, `DonationCampaignId`, `DonationCampaignName`, `TransactionDate`, `BookingUrlId`, `PaymentReceived`, `TicketQuantity`, `BookingFee`, `CardFee`, `ProcessingFee`, `Surcharge`, `ProcessingFeeSurcharge`, `TicketFee`, `TransactionType`, `PaymentType`, `EventPostcode`, `AccountPostcode`, `EventDate`, `Industry`, `SubIndustry`, `GatewayGroup`, `DGRStatus`, `CustomerId`, `IPCountry`, `Status`, `Wallet`, `GatewayName`, `GatewayId`, `GatewayReference`, `GiftCertificateTypeName`, `GiftCertificateId`, `BookingCountryCode`, `IPAddress`

### BookingDataAll (39 cols) — `YYYYMMDD-BookingDataAll-TBUK.csv`
Identical schema to BookingData, but the **full transaction history** to the file's date (~2.2 GB). Written periodically as a dated snapshot.

### Users (15 cols) — `YYYYMM-users-TBUK.csv`
User accounts and roles (one account can have several users).

`UserId`, `RoleId`, `RoleName`, `Username`, `FirstName`, `LastName`, `IsDeleted`, `AccountId`, `Unsubscribed`, `ProviderName`, `SmsMultiFactorEnabled`, `SecondFactorEnabled`, `MfaReminderDate`, `LastLoginDatetime`, `LastPasswordChangeDate`

> `Username` is the login email. The account owner is the user whose `RoleName` is `AccountOwner`.

## Balance & risk

### RiskReport (8 cols) — `YYYYMM-RiskReport-TBUK.csv`
Per-account balance and exposure — used to decide whether funds can be paid out.

`AccountId`, `AccountName`, `FullBalance`, `Balance`, `SalesForUpcomingEvents`, `Exposure`, `FutureDays`, `LastEventDate`

> `Balance` = available (excludes pending); `FullBalance` = incl. pending.

### AccountBalance (8 cols) — `YYYYMM-accountbalance-TBUK.csv`
Simpler per-account balance snapshot. Largely superseded by RiskReport.

`AccountID`, `AccountName`, `AccountCreationDate`, `AccountBalance`, `Industry`, `SubIndustry`, `GatewayGroup`, `DGRStatus`

### Account-Transactions (10 cols) — `YYYYMM-Account-Transactions-TBUK.csv`
Ledger of debits/credits against accounts (billing line items).

`Id`, `AccountID`, `Description`, `DebitAmount`, `CreditAmount`, `TransactionDate`, `IsAdditionalBilling`, `TransactionTypeId`, `TransactionType`, `BookingId`

## Movement / reconciliation ⚠️ (preamble files)

> **These four files start with a one-line metadata preamble**, *then* the real header on line 2. The preamble describes the gateway-batch range the file covers: `First Gateway ID, …, Start Booking Transaction ID, …, Last Gateway ID, …, End Booking Transaction ID, …`. When parsing, **skip line 1** (or detect that the real header begins with `AccountId` / `PaymentGatewayId` / `BookingTransactionId`).

### AccountMovement (43 cols) — `YYYYMM-AccountMovement-TBUK.csv`
Full account ledger movement (all-time totals per account) — ticket value, fees, refunds, gift certificates, balances.

`AccountId`, `DateTimeCreated`, `AccountName`, `TicketValue`, `FundraisingDonation`, `Donation`, `BoxOfficeFee`, `TotalBookingFee`, `TotalSurcharge`, `TotalProcessingFeeSurcharge`, `TotalCardFee`, `TotalTicketFee`, `TotalProcessingFee`, `TotalDonationFee`, `GCUsed`, `TicketRefundedAmount`, `FundraisingDonationRefunded`, `DonationRefundedAmount`, `BoxOfficeFeeRefundedAmount`, `TotalRefundedCardFee`, `TotalRefundedTicketFee`, `TotalRefundedProcessingFee`, `TotalRefundedSurcharge`, `TotalRefundedPFSurcharge`, `TotalRefundedDonationFee`, `ReturnedGCValue`, `RefundedGCValue`, `GCValue`, `GCDiscount`, `AdditionalCreditBilling`, `AdditionalDebitBilling`, `DebitListing`, `FundTransafer`, `BankVerfication`, `Recredit`, `Pending`, `OpeningBalance`, `ClosingBalance`, `Industry`, `SubIndustry`, `GatewayGroup`, `DGRStatus`, `StripeTransfers`

> `Pending` = amount currently in a transfer state — used by the funds/event reminder logic. (`FundTransafer` and `BankVerfication` are spelled that way in the source.)

### AccountMovementDaily (43 cols) — `YYYYMMDD-AccountMovementDaily-TBUK.csv`
Same 43-column schema as AccountMovement, but written **once per day** as a dated snapshot.

### GatewayMovement (32 cols) — `YYYYMM-GatewayMovement-TBUK.csv`
Same kind of movement totals but grouped **by payment gateway** instead of by account.

`PaymentGatewayId`, `PaymentGatewayName`, `TicketValue`, `FundraisingDonation`, `Donation`, `BoxOfficeFee`, `TotalBookingFee`, `TotalSurcharge`, `TotalProcessingFeeSurcharge`, `TotalCardFee`, `TotalTicketFee`, `TotalProcessingFee`, `TotalDonationFee`, `GCUsed`, `TicketRefundedAmount`, `FundraisingDonationRefunded`, `DonationRefundedAmount`, `BoxOfficeFeeRefundedAmount`, `TotalRefundedCardFee`, `TotalRefundedTicketFee`, `TotalRefundedProcessingFee`, `TotalRefundedSurcharge`, `TotalRefundedPFSurcharge`, `TotalRefundedDonationFee`, `ReturnedGCValue`, `RefundedGCValue`, `GCValue`, `GCDiscount`, `DebitListing`, `OpeningBalance`, `ClosingBalance`, `StripeTransfers`

### TransactionReconciliation (13 cols) — `YYYYMM-TransactionReconciliation-TBUK.csv`
Per-transaction reconciliation against the payment gateway — card, amount, payout.

`BookingTransactionId`, `TransactionDate`, `GatewayId`, `BookingUrlId`, `CardType`, `CardNo`, `Amount`, `Transaction`, `GatewayMessage`, `PayoutId`, `ArrivalDate`, `Provider`, `AccountName`

> `CardNo` is the last 4 digits only.

## Donations & other

### Transfers (4 cols) — `YYYYMM-transfers-TBUK.csv`
Bank transfer records.

`Amount`, `DateCreated`, `Filename`, `AccountId`

### DonationCampaigns (8 cols) — `YYYYMM-donationcampaigns-TBUK.csv`
Donation campaign pages (not used in the UK historically).

`Id`, `PageUrlHandle`, `AccountId`, `IsActive`, `PageName`, `Description`, `ContactEmailAddress`, `DateTimeCreated`

### Donations (17 cols) — `YYYYMM-donations-TBUK.csv`
Donation transactions.

`BookingId`, `BookingTransactionId`, `AccountId`, `AccountName`, `DateTimeCreated`, `EventId`, `EventName`, `TransactionDate`, `BookingFirstName`, `BookingLastName`, `BookingUrlId`, `Donation`, `PaymentType`, `Industry`, `SubIndustry`, `GatewayGroup`, `DGRStatus`

### Fundraising (6 cols) — `YYYYMM-fundraising-TBUK.csv`
Fundraising entity/ABN data (AU concept — minimal UK use).

`AccountId`, `AccountName`, `Current ABN`, `Current Entity Name`, `Txn ABN`, `Txn Entity Name`

### ScanAppUsers (6 cols) — `YYYYMM-scanapp-users-TBUK.csv`
Ticket-scanning app usage per event.

`AccountId`, `AccountName`, `EventId`, `EventName`, `TotalDevices`, `TotalScanned`
